# 息屏运行（关背光）

> 2026-10-29。Nubia Z17S / Linux 6.12.95 / MSM8998。
> 结论：**只关背光，不碰 framebuffer blank** —— 本机 DPU 的原子提交扛不住 `blank=4`。

---

## 0 一句话结论

```sh
z17s-screen off      # 息屏（背光 → 0），系统照常跑，SSH / 蜂窝 / Wi-Fi / 短信都不受影响
z17s-screen on       # 恢复（回到关屏前的亮度，默认 2048）
z17s-screen status   # 看当前亮度
```

开机由 `z17s-screen.service` 自动执行 `off`（`ExecStartPre=/bin/sleep 8`，
等显示栈初始化完再关，否则会被 mdss 的初始亮度覆盖）。

---

## 1 为什么不能用 `fb0/blank`

第一反应是 `echo 4 > /sys/class/graphics/fb0/blank`（标准做法），
但这台机器上写下去**立刻报 13 条 DPU 错误**：

```
[929.246314] [drm:dpu_encoder_phys_vid_wait_for_commit_done:541] [dpu error]vblank timeout: 40020041
[929.246340] [drm:dpu_kms_wait_for_commit_done:493] [dpu error]wait for commit done returned -110
[929.484205] [drm:dpu_encoder_frame_done_timeout:2456] [dpu error]enc32 frame done timeout
```

`-110` 是 `-ETIMEDOUT`。也就是说 mdss/dpu 的 atomic commit 在 blank 时超时，
面板并没有被干净地关掉。这个端口的显示栈不完整，走 blank 只会把 DRM 搞乱。

另外 `cat /sys/class/graphics/fb0/blank` 读出来是**空**（不是 `0`），
说明这个属性在本机基本是个摆设，连状态都读不回来。

## 2 背光这条路为什么干净

`/sys/class/backlight/backlight/`（`max_brightness=4095`，默认 `2048`）是纯 LED 亮度，
走 backlight 类，**不触发 DRM commit**。实测写 `0` 之后：

| 检查 | 结果 |
|---|---|
| `brightness` | `0`，20 秒后仍是 `0`（不被 mdss 覆盖） |
| `dmesg \| grep -c "dpu error"` | **13 → 13**，一条新增都没有 |
| 蜂窝 `rmnet0` | 正常（有 IP） |
| Wi-Fi | 正常（`999-5G` 已连） |
| SSH / 服务 | 正常 |

代价：面板本身还在通电（只是 LED 灭了），耗电不是零，但比常亮低一个量级。
对「当服务器用、屏幕别晃眼」这个需求足够。

## 3 文件

| 路径 | 说明 |
|---|---|
| `/usr/local/sbin/z17s-screen` | 开关脚本（`on` / `off` / `status`） |
| `/etc/systemd/system/z17s-screen.service` | 开机自动关屏（oneshot，`enabled`） |
| `/run/z17s-screen.brightness` | 关屏前的亮度备份（tmpfs，重启即失效） |

仓库对应 `scripts/screen/`。

---

## 4 排错

| 现象 | 处理 |
|---|---|
| `z17s-screen on` 后还是黑的 | 面板驱动没认 backlight 写；先 `status` 看值有没有变，再试 `echo 1 > /sys/class/drm/card0-DSI-1/dpms` |
| 开机后又亮了 | 说明有别的东西在改亮度，`systemctl status z17s-screen` 看是否 success，必要时把 `sleep 8` 加大 |
| 想临时调亮度 | `echo 1024 > /sys/class/backlight/backlight/brightness`（0–4095） |
| 误写了 `fb0/blank=4` | `echo 0 > /sys/class/graphics/fb0/blank` 恢复；dmesg 里会有 dpu error，属可恢复 |

---

## 5 红线

- **不要写 `fb0/blank`** —— 会触发 DPU commit 超时（见 §1）。
- 不要为了省电去动 `dpms` 之外的显示寄存器，本机 mdss 栈不完整。
- 关背光**不影响** modem / IPA / ath10k，纯显示层操作。
