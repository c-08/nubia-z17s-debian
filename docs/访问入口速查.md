## 1 三张网卡 —— 先搞清楚走哪条

| 接口 | 地址 | 来源 | 稳定性 | 角色 |
|---|---|---|---|---|
| `usb0` | `192.168.137.2/24` | USB gadget（RNDIS）静态 | **固定** | **主力**，PC 直连，0ms 延迟 |
| `wlan0` | `192.168.1.132/24` | 路由器 DHCP | **可能变** | 出门 / 不插线时用 |
| `rmnet0` | `10.46.87.181/30` | 运营商 | **每次开机都变** | 蜂窝上网 |
| `docker0` | `172.17.0.1/16` | docker | 固定 | 容器默认网桥 |
| `br-d3d7b22794d1` | `172.18.0.1/16` | docker compose | 固定 | 青龙所在网络 |

**默认路由优先级（metric 越小越优先）**：

```
default dev rmnet0            metric 50      ← 蜂窝，优先级最高
default via 192.168.1.1 dev wlan0  metric 600
default via 192.168.137.1 dev usb0 metric 1000
```

★ 这意味着**设备出网默认走蜂窝（受 3 Mbit/s 限速）**。想让某个命令走 Wi-Fi：
`curl --interface wlan0 …`（按**设备名**绑，按源 IP 绑会失败，见 §7）。

## 2 SSH

### 2.1 最快的方式（Windows 侧已配好别名）

```sh
ssh z17s
```

别名定义在 `C:\Users\admin\.ssh\config`：

```
Host z17s
    HostName 192.168.137.2
    User root
    IdentityFile C:\Users\admin\.ssh\z17s_ed25519
    StrictHostKeyChecking accept-new
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

★ **注意别名指向的是 `192.168.137.2`（USB）**，不是 Wi-Fi。
拔了 USB 线要改成 `192.168.1.132` 或者直接 `ssh root@192.168.1.132`。

### 2.2 认证策略（`sshd -T` 实测）

```
port 22
permitrootlogin without-password     ← root 只能密钥登录
passwordauthentication yes           ← 但密码登录对其他用户开放
```

★ 安全提醒：`PasswordAuthentication yes` 是开着的。这台机器现在同时挂在
家用 Wi-Fi 和蜂窝上，建议要么关掉密码登录，要么确认没有弱口令账户。

### 2.3 从别的电脑连

需要把公钥拷过去（`ssh-copy-id`），或者临时用密码登录非 root 账户。
USB 直连时 PC 侧地址是 `192.168.137.1`（Windows ICS 网关）。

## 3 串口控制台（救援通道）

### 3.1 现状：**只出内核日志，没有 shell**

```
/dev/ttyGS0                     存在（crw-rw---- root:dialout）
serial-getty@ttyGS0.service     masked      ← 被主动屏蔽了
```

屏蔽的原因见 [修复记录.md](修复记录.md) §16：agetty 反复重启会把 USB gadget 串口
打成 `gs_close` WARN。所以现在是**纯日志通道** —— 内核 `console=ttyGS0,115200n8`
仍然往这里输出，系统卡死时能看到最后的日志，但登不进去。

### 3.2 怎么用

- **Windows**：设备管理器里会出现一个 USB 串口（COMx），用 PuTTY / `putty -serial COMx -sercfg 115200`
- **Linux / macOS**：`screen /dev/ttyACM0 115200`（或 `ttyUSB0`）

### 3.3 真要 shell 的话（临时，用完关掉）

```sh
systemctl unmask serial-getty@ttyGS0.service
systemctl start  serial-getty@ttyGS0.service
# 用完
systemctl stop   serial-getty@ttyGS0.service
systemctl mask   serial-getty@ttyGS0.service
```

★ 不建议长期开着 —— 就是它导致的 `gs_close` WARN。

## 4 1Panel

```
地址: http://<IP>:28888/z17s_panel
用户: z17s
版本: v2.3.1 (stable)
```

★ **入口路径是 `/z17s_panel`，不是 `/`**。直接访问 `http://<IP>:28888/` 会 404。

密码被 `1pctl user-info` 掩码成 `********`，**看不到原文**。忘了就重置：

```sh
1pctl update password        # 交互式输入新密码
```

监听：`1panel-core` 绑 `0.0.0.0:28888`，LAN / USB 都能访问。

## 5 青龙面板

```
地址: http://<IP>:5700
容器: qinglong（whyour/qinglong:2.21.0-debian）
端口: 0.0.0.0:5700 -> 5700/tcp（docker-proxy）
```

**账号**：默认 `admin`，初始密码在容器首次启动日志里（`docker logs qinglong | grep -i password`）。

忘了就重置（容器内 `ql` 支持的子命令，实测可用）：

```sh
docker exec -it qinglong ql resetpwd      # 改密码
docker exec -it qinglong ql resetname     # 改用户名
docker exec -it qinglong ql resetlet      # 重置登录错误次数（被锁了用这个）
docker exec -it qinglong ql resettfa      # 关掉两步验证
```

★ 青龙的 Debian 容器里**没有 `apk`**，装依赖用 `apt`（[使用说明.md](使用说明.md) §4.1 记过这个坑）。

## 6 短信服务（DbusSmsForwardCPlus）

```
网页: http://<IP>:1102/
发信 API: http://<IP>:1102/api?telnum=<号码>&smstext=<内容>
```

无认证，**任何能连上这台机器的人都能发短信**。用完建议只在内网暴露。

## 9 连不上时先看什么

| 现象 | 检查 |
|---|---|
| `ssh z17s` 超时 | USB 线插了吗？PC 侧 `192.168.137.1` 能 ping 通吗？`ip -4 addr show usb0` |
| Wi-Fi 连不上 | 路由器 DHCP 换了地址。上 USB 查 `ip -4 addr show wlan0`，或看路由器后台 |
| 面板 404 | 1Panel 必须带 `/z17s_panel` 路径 |
| 面板打不开但 SSH 通 | `ss -lntp \| grep 28888`；`systemctl status 1panel-core` |
| 青龙打不开 | `docker ps` 看容器是否在跑；`docker logs --tail 50 qinglong` |
| 1102 没响应 | `systemctl status dbussms`；`journalctl -u dbussms -n 50` |
| `curl --interface 192.168.1.132` 全 `000` | **按源 IP 绑会失败**，改 `--interface wlan0` |
| 串口没输出 | 内核 cmdline 有 `console=ttyGS0`，但 getty 是 masked —— 只有日志没有提示符，属正常 |

## 10 安全建议（这台机器现在同时挂在三个网上）

1. `PasswordAuthentication yes` 建议关掉，只留密钥。
2. 短信 API（1102）**无认证**，能发真实短信，别暴露到公网。
3. 1Panel 已用自定义入口 `/z17s_panel`，别再改成 `/`。
4. 蜂窝是公网出口，但 `rmnet0` 没有公网入站（运营商 NAT），风险主要来自 LAN。
