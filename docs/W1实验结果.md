# W1 实验结果（2026-09-25 夜，已上机）

## TL;DR

| 问题 | 答案 |
|---|---|
| 设备恢复了吗 | ✅ **已恢复**，正常开机（TWRP + `dd` 写入，回读 md5 校验通过） |
| W1 补丁部署了吗 | ✅ 已部署且**持久**（重启后 `/lib/modules` 里就是补丁版） |
| 软解路径打通了吗 | ✅ **打通**（`hwcrypto 0` + `key_hw_accel SW ok (drv ret=1)`） |
| WPA2 握手？ | ✅ **成功了**（`WPA: Key negotiation completed [PTK=CCMP GTK=CCMP]`，三次重试都成功） |
| Wi-Fi 能上网吗 | ❌ **不能**。我们的加密帧发不出去 → AP 以 `4WAY_HANDSHAKE_TIMEOUT` 踢人 → 固件仍 assert |
| 设备会被打死吗 | ✅ 不会（这次 WiFi 开着撑了 8 次崩溃没死机；`nmcli radio wifi off` 后 load 回落到 0.38） |

**一句话**：W1 把失败点从「WPA 装密钥阶段固件崩」推进到「握手成功、但加密帧发不出去」，
**软解这条路本身走通了，卡在固件不发软件加密的帧**。Wi-Fi 仍未可用。

## 2 三条决定性证据（都直接从设备取的原文）

```
[   31.308988] WCN3990: SW crypto without raw mode, HW crypto disabled        ← 补丁 A 生效
[   31.370925] ... raw 0 hwcrypto 0                                           ← nohwcrypt=true（以前永远做不到）
[  287.687197] key_hw_accel SW ok (drv ret=1)                                 ← mac80211 真的走软件解密分支
[  287.687213] ieee80211_add_key done err=0 pairwise=1 idx=0 mac=a6:a9:30:d4:0c:ea
[  290.738836] wlan0: deauthenticated ... (Reason: 15=4WAY_HANDSHAKE_TIMEOUT)  ← AP 踢人
[  296.006355] EX:wlan_process:1:WLAN RT:207a:PC=b00c0098                     ← 固件 assert（RT 从 1078 变 207a）
```

**成功的那一半**：密钥不再下发给固件（`drv ret=1`），WPA2 四次握手在本地完整走通，
`PTK=CCMP GTK=CCMP` —— 这正是 `cipher=0xfac04`（CCMP-128，标准 WPA2）对应的结果。

**失败的那一半**：本地握手成功、AP 却没收到我们的加密帧 ⇒ `4WAY_HANDSHAKE_TIMEOUT`。

## 3 卡点的机制（源码级）

`unhandled tx completion status 5` 出处 = `htt_rx.c:2974`：

```c
int status = MS(resp->data_tx_completion.flags, HTT_DATA_TX_STATUS);
switch (status) {
case HTT_DATA_TX_STATUS_OK / NO_ACK / DISCARD / POSTPONE:  ...
default:
    ath10k_warn(ar, "unhandled tx completion status %d\n", status);   // ← 5 落到这里
    tx_done.status = HTT_TX_COMPL_STATE_DISCARD;                       // ← 一律当"丢弃"
}
```

`HTT_DATA_TX_STATUS_MASK = 0x07`，本驱动只定义到 `POSTPONE = 3` ⇒ **状态 5 是这颗 HL1.0 固件
自造的状态码，Linux 侧不认识**，于是所有这类帧被当成 DISCARD。

那为什么会被固件丢弃？驱动侧我们确实按"软解"送了帧（`mac.c:3805`）：

```c
static bool ath10k_tx_h_use_hwcrypto(...)
{
    if (!ieee80211_has_protected(hdr->frame_control)) return false;
    if ((info->flags & mask) == mask)                 return false;
    if (vif) return !((struct ath10k_vif *)vif->drv_priv)->nohwcrypt;   // nohwcrypt=true → false
    return true;
}
```
返回 `false` ⇒ 该帧带 `ATH10K_SKB_F_NO_HWCRYPT` ⇒ HTT 描述符置 `NO_ENCRYPT`，告诉固件
"这帧已由 host 加好密，你直接发"。**实测结论：HL1.0 固件不认这个标记**
（`nohwcrypt` 这条路径在这颗芯片上从没被上游验证过）。

### ★ 顺带发现一个从前不知道的开关

`modinfo -p ath10k_core.ko` 里有：

```
cryptmode : Crypto mode: 0-hardware, 1-software (uint)
frame_mode: Datapath frame mode (0: raw, 1: native wifi (default), 2: ethernet) (uint)
```

而 `core.c:2663-2700` 的编译期逻辑是：

```c
ar->wmi.rx_decap_mode = ATH10K_HW_TXRX_NATIVE_WIFI;
switch (cryptmode) {
case HW: clear RAW_MODE; clear HW_CRYPTO_DISABLED; break;
case SW: if (!RAW_MODE_SUPPORT) { <WCN3990 补丁：只置 HW_CRYPTO_DISABLED>; break; }
         set RAW_MODE; set HW_CRYPTO_DISABLED; break;
}
if (frame_mode == ATH10K_HW_TXRX_RAW) {
    if (!RAW_MODE_SUPPORT) { ath10k_err("rawmode = 1 requires support from firmware"); return -EINVAL; }
    set RAW_MODE;
}
if (RAW_MODE) {
    ar->wmi.rx_decap_mode = ATH10K_HW_TXRX_RAW;
    ar->htt.max_num_amsdu  = 1;        // ← 顺带关掉 A-MSDU（正是当年怀疑的那条）
    ...
}
```

三点含义：

1. **上游的软解配置其实是"RAW 数据面 + 软解"**（`cryptmode=1` 就要求 `RAW_MODE_SUPPORT`）。
   我们的补丁绕开了 RAW_MODE，走的是**厂商自创的"非 raw 软解"**——这才是 TX 被丢的嫌疑所在：
   RAW 模式下 `htt_tx.c:1430/1636` 那条分支（`!NO_HWCRYPT && txmode==RAW && protected` → 给 MIC 留位）
   才是为软解设计的。我们现在既非 raw、又标 NO_ENCRYPT，可能两头不靠。
2. **想用 `frame_mode=0` 会直接让模块加载失败**：`-EINVAL` → 连 `wlan0` 都不会有。
   要试它，必须再放宽这道门槛（补丁 C）。
3. RAW_MODE 会**顺带把 A-MSDU 关成 1**，这正好可以一次性把"聚合"那条老怀疑一起验证。

## 3.1 ⚠️ 补充实测：崩溃风暴**在 WiFi 关闭后不会自停**

这是本次新增的、对以后操作很重要的一条：

| 动作 | 结果 |
|---|---|
| `nmcli radio wifi off` | 崩溃**继续**（每 ~41.7 s 一次） |
| 再 `nmcli dev disconnect wlan0` + `ip link set wlan0 down`（`wlan0` 变 DOWN/unavailable） | 崩溃**仍然继续** |

实测：断开后 80 秒内计数 `20 → 22`（两组都符合 ~41.7 s 周期）。

**周期为什么是 41.7 s**：崩溃 → `remoteproc` 重启整个 MSS（~2.5 s 起来）→ **Wi-Fi 固件被重新下载并初始化
（开机实测这段要 ~25 s）** → 再次 assert。也就是说**是驱动/固件的重启恢复路径自己在循环**，
与"有没有业务在用 WiFi"无关。

**处置（按代价从小到大）**：

1. 想继续用这台机器但不折腾：**直接 `reboot`** —— 干净重启后 WiFi 默认是关的（`nmcli radio wifi off` 持久），
   实测可以稳定跑 45 分钟以上、崩溃 0 次。
2. 想省一次重启：`modprobe -r ath10k_snoc ath10k_core`（⚠️ 历史记录：拆了之后 `wlan0` 往往要重启才回来，
   所以**只在"今天不再试 WiFi"时才用**）。
3. 🔴 **别在崩溃环里继续操作 wlan0**（`iw scan` / `nmcli` 都只是陪跑）。

> 这也是"WiFi 开着 = 机器变慢"的真正原因：不是 CPU 被业务占满，而是**每 40 秒重载一次几十 MB 的 modem 固件**。

## 4 下一步候选实验（按性价比排序）

> 🔑 **先说一个能省掉刷机的技巧**：模块是 `=m`，而 initramfs 只在**开机时**把 ramdisk 的
> `/lib/modules` 拷进 rootfs。所以**运行中**可以直接换 `/lib/modules/.../ath10k_core.ko` 再
> `modprobe -r ath10k_snoc; modprobe ath10k_snoc` 来试不同变体 —— **不用刷 boot、不用重启**。
> 只有"要它开机默认生效"时才需要重做 boot 镜像（并重新签名）。
> ⚠️ 已知风险：历史上 `modprobe -r ath10k_snoc` 有过"wlan0 再也不出现"的记录，所以第一次试要留退路（`usb0`/串口都在）。

| # | 实验 | 成本 | 能回答什么 |
|---|---|---|---|
| **E1** | 换一个**明文（无加密）AP** 连一下 | 0（用户开个热点，无密码） | **决定性**：若明文也不崩 → 触发点就是加密路径；若明文也崩 → 加密从来不是真凶，得改查频段/省电/regdb |
| **E2** | `cryptmode=1` + **放宽 `frame_mode=0` 门槛**（补丁 C：连 `rawmode=1 requires support` 那道也放行） | 小（改 3 行 + 重编 40 s + 活系统换 .ko） | 走上游正统的"RAW + 软解"，顺带关 A-MSDU。若固件真不支持 raw，会在 probe 报错（可当场回滚） |
| **E3** | 连路由器 **2.4 GHz**（ch6/ch11）AP | 0（需要 SSID/密码） | 排除 5 GHz / `regulatory downgraded` 这条线 |
| **E4** | 同一 AP + `iw dev wlan0 set power_save off` | 0 | 老怀疑的 PS 那条（**从来没试过**） |
| **E5** | 关掉厂商补丁 `skip idle_ps_config`（重编） | 小 | 该补丁是否本身有害 |

**建议顺序：E1 → E3/E4（都是零成本，一次开机全部跑掉）→ 再决定 E2。**

**止损线（沿用原方案）**：WiFi 开着 30 分钟内若再出现 `EX:wlan_process`，立即 `nmcli radio wifi off`，
并把日志存 `/root/`；连续 2 轮都无进展就停手（Wi-Fi 对这台机器的实际价值不高，见 §6）。

## 5 本轮副产品

1. **设备恢复通道的真相**：本机 fastboot **不能刷分区**（见 `docs/boot镜像签名与恢复.md` §5.2 实测更正）。
   唯一可用通道 = **TWRP（音量上+电源）+ `adb push` + `dd`**。
   本次：`dd if=/tmp/boot_w1.img of=/dev/block/sde18 bs=4096` → 16384 记录、回读整分区 md5 `84c37378…` 一致。
2. **`M=` 编出来的模块会让内核 `taints kernel`**（`loading out-of-tree module taints kernel`）——
   因为丢掉了 `MODULE_INFO(intree,"Y")`。纯属标记，不影响功能，但会让 dmesg 多一行、并让
   `lockdep`/`oops` 报告被标为 "unsupported"。要免掉它，得让 modpost 按 in-tree 处理（未做）。
3. **模块变体可"活系统热换"**（见 §4 引言），把每次实验从"刷机 3 分钟 + 按键"降到"scp + 两条命令"。

## 6 结论与建议

- W1 **不是**"能修好 Wi-Fi"的方案，但它**把最后一条没试过的路试完了**，而且证明
  「软解本身能生效、WPA2 握手能过」——剩下的卡点是固件不肯发软件加密的帧。
- 单看收益：这台机器有 `usb0`（ping 0 ms、稳定），Wi-Fi 价值有限；**建议把精力放回蜂窝（IPA）**，
  Wi-Fi 只做零成本的 E1/E3/E4，或最多做一次 E2。
- Wi-Fi 现状：**保持 `nmcli radio wifi off`**（稳定、零崩溃、load 0.38）。
