## 2 三个决定性修复

### 2.1 insmod 必须在 modem 注册之后

**现象**：开机 40–90 s 就 `insmod`，QMI 握手、建承载全部成功，`rmnet0` 也能拿到运营商 IP，
但 `ping` 100% 丢包，modem 侧 `tx_pkts_ok` 恒为 0 —— 典型的"假连接"。

**判据**（modem 侧才是真指标）：

```sh
qmicli -d qrtr://0 -p --wds-get-packet-stats   # 或呼叫日志里的 tx_pkts_ok
```

**修复**：等 `uptime ≥ 410 s` 再 `insmod`（此时 modem 已 `online` + `registered`，DS 已落定）。

**推测机理**：早 insmod 时 modem 的 IPA 客户端在 DS 未就绪时初始化，之后建出的 embedded call
是空的 —— 包进得了 GSI ch5，modem 的 `ipa_ul` 不认。

> 注意：这个时序是**和 ep16 聚合独立**的两个变量。10-28 曾把"insmod 时间"单独否掉过一次，
> 但那次是在没有真实承载的情况下测的，结论不可信。

### 2.2 ep16 聚合旁路 —— 下行只上送 38% 的真因

这是本次最有价值的技术发现，**跟"数据面没通"完全是两回事**。

**症状**：上行通了、`ping` 通，但下载只有 **2.3 KB/s**；`ipa_rx` 与 `rmnet0_rx` 包数 1:1，
而字节数差 **2.6 倍**（大包进、小包出）。

逐层定量（12 秒下载）：

| | IPA 层增量 | rmnet0 层增量 | curl 实收 |
|---|---|---|---|
| 第一次 | +82 包 / +271 KB | +80 包 / +102 KB | 26 KB |
| 第二次 | +98 包 / +310 KB | +96 包 / +120 KB | 18 KB |

抓 GSI 收到的原始字节：

```
GSI len=4236  00 00 05 78 | 45 08 05 78 db 43 40 00 ...
              └flags┘└mux┘└pkt_len=1400┘
GSI len=5648  00 00 05 78 | ...
GSI len=7060  00 00 05 78 | ...
```

**根因**：IPA 硬件把下行的多个 IP 包聚合成一个 GSI 帧，**但 QMAP 头的 `pkt_len` 只写了第一个包的
长度（1400）**。本驱动在 `ipa_endpoint_skb_build()` 里把整帧直接交给协议栈（ep16 没有
`status_enable`，走 skb_build 路径，**没有任何 QMAP deaggregation**），
`rmnet_map_ingress_handler()` 只 `skb_trim` 到 `pkt_len` 就上送，**剩下的 2836 字节整段丢弃**。
⇒ 下行只上送约 38%，与 271 KB→102 KB 完全吻合。

**修复**（运行期一条命令，不用重编）：

```sh
echo 16 > /sys/module/ipa/parameters/z17s_aggr_reg     # 只读，看当前值
# Z17SAGGRREG ep=16 before=0x2004d1 en=1 type=4 byte=6 time=1 pkt=0 eof=1 fc=0 hard=0

echo "16 0" > /sys/module/ipa/parameters/z17s_aggr_reg # BYPASS_AGGR
# Z17SAGGRREG ep=16 wrote=0x0 after=0x0 aggr_active0=00000000
```

效果（同一 boot、同一呼叫、**只改这一处**）：

| | 关聚合前 | 关聚合后 |
|---|---|---|
| 吞吐 | 2.3 KB/s | **324–366 KB/s** |
| 包长 | 4236 / 2824 / 5648 / 7060 | 全是 1412 |
| 收包 | ipa +3608 / rmnet0 +3606（字节差 2.6×） | **1:1，零丢失** |

**源码里其实早就有这个修复**：`ipa_data-v3.1.c` 的 `IPA_ENDPOINT_AP_MODEM_RX` 配置项里
`.aggregation = false`，注释写着"100pps 37% loss -> 0%, 50pps 6% -> 0%"。
但它只在 `ipa-new-148.ko` 里生效；本次为了对齐 10-27 那次成功用的是 `ipa-new-147.ko`，
那里还是 `true`。**所以要么换 148.ko，要么在 147 上运行期写 `z17s_aggr_reg`** —— 我们选了后者。

### 2.3 ep18 聚合旁路（上行）

```sh
echo "18 0" > /sys/module/ipa/parameters/z17s_aggr_reg
# Z17SAGGRREG ep=18 before=0x1907f1 -> wrote=0x0 after=0x0
```

`0x1907f1` 解码：`AGGR_EN=1, AGGR_TYPE=4(GENERIC), BYTE_LIMIT=31, TIME_LIMIT=1, PKT_LIMIT=50`。
关掉后上行立刻正常计数。


## 5 踩过的坑 / 旧结论纠正

### 5.1 SIM 卡：新卡在这版固件上初始化不了

```
旧卡（槽 1）: Application state 'ready' / PIN1 retries 3 / PUK1 10 /
             Provisioning "Primary GW: slot '1', application '1'"     ← 完全正常
新卡（槽1/槽2）: 'detected' / PIN1 retries 0 / "session doesn't exist"  ← 初始化不了
```

`PIN1 retries = 3` 是关键：**要读出这个数字，modem 必须真的把卡里的 EF 读完了**。
新卡恒为 0，因为一个文件都没读到。

新卡画像：回了 ATR（`Card state: 'present'`，掉电会变 `no-atr-received`），
失败点在 ATR 之后的双向 APDU：

```
--uim-read-transparent=0x3F00,0x2FE2   → error (3)  'Internal'
--uim-send-apdu=1,1,00A40004022FE2     → error (48) 'InvalidArgument'
--uim-open-logical-channel=1,<AID>     → 成功 channel=1（MANAGE CHANNEL 通）
```

已排除：运营商锁（`Personalization: all disabled`）、槽位（`--uim-switch-slot` 返回
`NotSupported`，单槽固件）、3G/2G 退网（强制 `lte,automatic` 仍 `limited`）、SIM 上下电、
`--uim-reset`、`--dms-set-operating-mode=reset`、provisioning session、时序/race。

⇒ **卡座、modem、UIM 通路、NV、provisioning 全部正常，是这张新卡不兼容。**
**F3 抓不到 UIM 的 APDU** —— 全掩码抓了 297 条文本帧、覆盖开机 12–102 s，
UIM 相关只有 1 条 `uimqmi.rcinit_rex.c`，ATR/APDU/ICCID/PIN 关键字全 0。别再试。

### 5.2 modem 卡在 `shutting-down` 可以先发 `online` 救回来

```sh
qmicli -d qrtr://0 -p --dms-get-operating-mode          # Mode: 'shutting-down'
qmicli -d qrtr://0 -p --dms-set-operating-mode=online   # Operating mode set successfully
# 紧接着就 registered + PS attached，不必物理断电
```

冷启动后也可能仍是 `shutting-down`，不是只有热插拔才会。**绝不发 `offline`。**

### 5.3 换卡必须断电换

带电热插拔 SIM 会让 modem 进 `shutting-down`，当次 boot 报废（NAS 全 detached、
`--nas-get-signal-info` 返回 `InformationUnavailable`）。

### 5.4 `ipa.ko` 三个版本别搞混

| 文件 | md5 | 说明 |
|---|---|---|
| `ipa-new-147.ko` | `9acc6dc6…` | 10-27 那次成功 + **10-29 打通**用的二进制（ep16 聚合仍为 true） |
| `ipa-new-148.ko` | `7a6a94ec…` | 147 + ep16 `.aggregation=false` + TX 唤醒，差 20 B，**未在真实承载下验证** |
| `ipa-z17s-148.ko` | `73bae150…` | 差 37311 B 的另一次构建，**`z17s_aggr_reg` 上任何 ep 都 EINVAL**，别用 |

### 5.5 极易误判的假象

1. AP 侧 ch5 TX 完成事件照常回环（GSI 硬件在排空）⇒ 看着像"上行正常"。
2. `ridx=249 / avail=0` 是 init 布防后的正常残留（`gsi.c:2956` 打的是驱动侧写指针），
   不是"收到 249 个包"。
3. `tre_reserve FAIL need=1 avail=0` 每包一次，**不是瓶颈** —— 它是 RX ring 满载的正常表现。
   吞吐问题 100% 是聚合，别去追 TRE 池。
4. `--wds-get-packet-service-status` 在**另一个 qmicli client** 里返回 `disconnected`
   是正常的（WDS 呼叫是 per-client 的）。
5. `Slot [2]: no-atr-received` 是空槽，正常。
6. 日志时间不可信（NTP 跳变）—— 时序一律用 **dmesg 单调时间 + `/proc/uptime`**。

### 5.6 `[10] 自检` 的一个判定 bug（已修）

`z17s_aggr_reg` 每写一次会打**两行** `Z17SAGGRREG`（`before` / `wrote`）。
用 `tail -1` 拿到的是 `wrote=0x0 after=0x0`（没有 `en=` 字段），所以 `case *"en=0"*` 匹配不上，
会误报"聚合未关"。正确写法：

```sh
AG=$(dmesg | grep -a Z17SAGGRREG | tail -2 | head -1 | sed "s/.*Z17SAGGRREG //")
```

## 6 复现步骤

```sh
# 0) 前置：modem 起来、卡 ready、已注册
qmicli -d qrtr://0 -p --uim-get-card-status      # Application state 'ready'
qmicli -d qrtr://0 -p --dms-get-operating-mode   # 若 'shutting-down' 先发 --dms-set-operating-mode=online
qmicli -d qrtr://0 -p --nas-get-serving-system   # Registration 'registered' / PS 'attached'

# 1) 等 DS 落定（脚本里是 registered 后再等 POSTREG=30s）
sleep 30

# 2) 装驱动（全套参数）
insmod /root/ipa-new-147.ko z17s_hdr_len=4 z17s_noqstop=1 z17s_notif=1 \
       z17s_notif_fidx=1 z17s_notif_pipe=5

# 3) 等 rmnet_ipa0 出现，然后关两个方向的聚合 —— 下行这条最关键
sleep 2
echo "18 0" > /sys/module/ipa/parameters/z17s_aggr_reg
echo "16 0" > /sys/module/ipa/parameters/z17s_aggr_reg
echo N    > /sys/module/ipa/parameters/z17s_rx_dump

# 4) 建 rmnet0 并 up（不要动 rmnet_ipa0 的 link 状态）
ip link add link rmnet_ipa0 name rmnet0 type rmnet mux_id 0
ip link set rmnet0 up
echo 0 > /sys/class/net/rmnet0/ipv6/conf/all/disable_ipv6

# 5) QMAP 数据格式
#    （见 z17s-up.sh 的 [7] 段）

# 6) 单进程 QMI 客户端建承载（必须单进程，见 G3 文档 §1.1）
cd /root && BIND_MODE=before setsid python3 qmi87.py 3gnet 3 16 1 0 14400 \
    > /root/z17s-call.log 2>&1 < /dev/null &

# 7) 等 IP，加默认路由，验收
sleep 45
ip -4 addr show rmnet0 | grep inet
ip route replace default dev rmnet0 metric 50
ping -I rmnet0 -c 10 223.5.5.5
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" http://www.baidu.com/
```

**一键版**：`sh scripts/cellular/z17s-up.sh`（APN 按 PLMN 自动选：460-01/06/09 → `3gnet`）。
开机自动版：`scripts/cellular/z17s-late.service` + `z17s-late.sh`。

## 7 红线（违反即崩 modem / 丢证据）

1. **`ip link set rmnet_ipa0 down` 无条件致命**；G4 那次冻死整机的问题**没有根治**，
   本方案是绕开它 —— 全程不碰 `rmnet_ipa0` 的 link 状态。
2. 严禁热卸载 / 热重载 `ipa.ko`、modem stop/start、运行期 GSI/TABLE_INIT、
   `z17s_ep_cycle`、`z17s_gsi_ee*`（读 EE≥1 总线中止）、`z17s_patch_dst_ep`、`z17s_ready_go`。
3. **同一 mux 绝不建第二条呼叫**（`ds_rmnet_meta_sm.c:5285 Assertion 0` 崩 mss，只能物理断电）。
   `pkill qmi87.py` 不会 `stop_network`，旧 bearer 仍留在 modem 里。
4. **`rmnet0` 每 boot 必须重建**。
5. **收尾一律物理断电，不得 `reboot`**（卡 `alsactl`，长按电源 10–15 s）。断电前 `sync ×3`。
6. F3 掩码**绝不能全开**（`0xFFFFFFFF` × 25 段会让 modem 任务饿死，看门狗每 18 s 崩一次）。
