## 1 最终配置

| 项 | 值 |
|---|---|
| 服务 | `dbussms.service`（enabled，`WantedBy=multi-user.target`） |
| 启动命令 | `/root/sms/DbusSmsForwardCPlus -fS --configfile=/root/sms/config.txt --sendsmsapi=enable` |
| 转发渠道 | `-fS` = **Shell 脚本**（`/root/sms/forward.sh`，无需任何 token） |
| 端口 | `config.txt` 里 `apiPort = 1102` |
| 短信存储 | `me`（模组内存，默认）+ `sm`（SIM 卡） |
| 二进制 | `/root/sms/DbusSmsForwardCPlus`（618688 B，`/root/sms/src/` 是源码） |
| 回滚 | `/root/sms/DbusSmsForwardCPlus.bak`（未打补丁的原版） |

### 为什么选 `-fS`（Shell）

Email / PushPlus / 企业微信 / TG / 钉钉 / Bark 六个渠道都要先填 token，
Shell 模式是唯一**零凭据就能跑**的。`forward.sh` 现在只做落盘记录，
要推到别处就在里面加一行 `curl`（文件里已备好 4 个渠道的示例注释）。

### 短信相关的两个坑

1. **必须用 `mmcli` 读，不能用 `qmicli`。**
   本机 `qmicli` 是 1.36.0，它的 WMS 只实现了 `get-supported-messages` / `get-routes` /
   `set-routes` / `reset` / `noop`，**没有 list / get / send**。
   （另外 `--wms-get-supported-messages` 在这版固件上返回 `InvalidQmiCommand (71)`，
   那是可选项，不影响使用。）

2. **`mmcli` 命令行打不出中文。**
   `mmcli -s N` 显示 `text: ??`，但 D-Bus 里的 `Text` 属性是**正确 UTF-8**：

   ```sh
   busctl get-property org.freedesktop.ModemManager1 \
     /org/freedesktop/ModemManager1/SMS/1 \
     org.freedesktop.ModemManager1.Sms Text
   # s "\346\265\213\350\257\225"   ← 就是「测试」
   ```

   所以是终端 locale 问题，不是解码问题。插件走 D-Bus，中文正常。

## 2 为什么原版跑不起来：三个必须修的 bug

上游 v1.0.7 在 MM 1.24 上**直接不可用** —— API 永远回 `ok` 但一条也发不出去，
转发也一条都收不到。三个 bug 层层叠在一起：

### 2.1 `Create` 的 modem 路径写死成 `Modem/0`

```c
"/org/freedesktop/ModemManager1/Modem/0",   // ← 原版
```

本机模组是 **`Modem/1`**（MM 的对象编号每次开机不固定）。
结果 `Create` 报 `UnknownMethod: Object does not exist at path .../Modem/0`，
`smsSavePath` 为空，后面的 `Send` 压根没执行 —— 而 webapi 无条件回 `ok`，所以完全看不出来。

**修**：新增 `getModemPath()`，用 `org.freedesktop.DBus.ObjectManager.GetManagedObjects`
扫出 `…/Modem/N`。顺带发现 **MM 1.24 已经删掉了 manager 的 `Modems` 属性**
（老教程里读 `Modems` 的方法在这里会 `No such property`）。

### 2.2 监听信号的 match 规则也写死成 `Modem/0`

```c
dbus_bus_add_match(connection,
  "type='signal',path='/org/freedesktop/ModemManager1/Modem/0',interface='...Modem.Messaging'", &error);
```

路径不对 ⇒ **一条 `Added` 信号都收不到**，转发永远不触发。

**修**：去掉 `path` 约束，只按 `interface` 匹配。

### 2.3 收发共用同一条 D-Bus 连接（会挂死）

`dbus_bus_get()` 返回的是**共享连接**。原版 `monitorDbus` 在一个线程里
`read_write` + `pop_message`，`sendSms` 在另一个线程里用**同一条连接**发请求等回复，
而且超时传的是 `-1`（永不超时）。

一旦监听线程把回复消息 `pop` 走，发送线程就永远等不到回复 —— **卡死**。

**修**：发送侧全部改用 `dbus_bus_get_private()` + `dbus_connection_close()`，
超时从 `-1` 改成 `15000` ms。

### 2.4 附带修的两处

- `dbus_message_append_args` 传字符串参数时误传了 `&ptr`（应该是 `ptr`），
  改用 `dbus_message_iter_append_basic`，语义明确。
- webapi 原来无论成败都回 `ok`，改成回 `ok` / `fail`，并对缺参数回 HTTP 400。
  错误信息也从「只认 Unknown method」改成打印真实 D-Bus 错误名 + 内容。

补丁：**[`scripts/sms/z17s-dbussms.patch`](../scripts/sms/z17s-dbussms.patch)**（265 行，2 个文件）

## 4 转发到别处怎么改

编辑 `/root/sms/forward.sh`，脚本会收到 6 个参数：

| 位置 | 含义 |
|---|---|
| `$1` | 发信号码 |
| `$2` | 收信时间 |
| `$3` | 短信内容 |
| `$4` | 验证码（自动提取，没有则为空） |
| `$5` | 验证码来源 |
| `$6` | 设备名 |

默认只写 `/root/sms/sms.log`。要加渠道就在文件里取消对应注释：

```sh
# Telegram
curl -s --max-time 10 "https://api.telegram.org/bot<TOKEN>/sendMessage" \
  --data-urlencode "chat_id=<CHAT_ID>" --data-urlencode "text=[$DEV] $NUM: $TEXT" >/dev/null

# Bark
curl -s --max-time 10 "https://api.day.app/<KEY>/$NUM/$TEXT" >/dev/null

# 企业微信机器人
curl -s --max-time 10 -H 'Content-Type: application/json' \
  -d "{\"msgtype\":\"text\",\"text\":{\"content\":\"[$DEV] $NUM\n$TEXT\"}}" \
  "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<KEY>" >/dev/null
```

改完不用重启服务（每次转发都重新 `system()` 调用脚本）。

想换成插件自带的渠道（Email/PushPlus/企业微信应用/TG Bot/钉钉/Bark），
改 `dbussms.service` 的 `-fS` 为对应参数（`-fE` `-fP` `-fW` `-fT` `-fD` `-fB`），
再在 `config.txt` 里填 token，然后 `systemctl daemon-reload && systemctl restart dbussms`。

## 5 排错

| 现象 | 原因 / 处理 |
|---|---|
| API 回 `ok` 但没收到短信 | 原版 bug，见 §2.1。确认用的是打过补丁的二进制 |
| API 回 `fail` | 看 `run.log` 里 `创建短信失败:` 后面的 D-Bus 错误名 |
| 收到短信但不转发 | §2.2：match 规则路径不对。确认 `run.log` 有 `SmsPath:` 输出 |
| 发短信卡住不返回 | §2.3：共享连接被抢。确认超时是 15000 不是 -1 |
| `mmcli -s N` 显示 `??` | 终端 locale，不是数据问题，见 §1 |
| 端口 1102 没监听 | `journalctl -u dbussms -n 50`；多半是 `config.txt` 里 `apiPort` 空 |
| `Create` 报 `UnknownMethod` | modem 路径错。`busctl tree org.freedesktop.ModemManager1` 看真实编号 |

## 6 红线

- **不要 `systemctl restart ModemManager`** —— 会重新枚举模组，`rmnet0` 掉线，
  蜂窝要重建呼叫（同一 mux 不能建第二条，会崩 mss）。
- **不要在蜂窝活动时卸载 `ipa.ko`** —— 见 [蜂窝G5](蜂窝G5-数据面打通.md) §7。
- 短信读写走 QMI WMS，**完全不碰 IPA 数据面**，不影响蜂窝。
- `dbussms.service` 里写了 `Requires=ModemManager.service`（单向依赖，不会反过来影响 MM）。

## 7 复现

```sh
# 设备上，仓库脚本目录内
sh scripts/sms/install-dbussms.sh 1102
```

脚本做五件事：装编译依赖 → 下载上游源码并打补丁 → 编译 →
部署到 `/root/sms` → 装 systemd 单元并启用。

首次编译约 3.5 分钟（MSM8998，`httplib.h` + `rapidjson` 比较吃 CPU）。
