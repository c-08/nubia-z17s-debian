# 系统备份与恢复

> 目标：**无论搞坏什么，都能回到一个已知可用的状态。**

---

## 一、备份策略（三层，按恢复能力递增）

| 层级 | 内容 | 体积 | 耗时 | 能救回什么 |
|---|---|---|---|---|
| **T1 关键分区** | boot + persist + 配置 + 包列表 | ~20 MB | 20 秒 | 开不了机、Wi-Fi MAC 丢失、配置被改乱 |
| **T2 根文件系统** | 整个 `/` 打包 | ~1.5 GB | 5–10 分钟 | 系统被搞坏、误删文件、想整机迁移 |
| **T3 整盘镜像** | 全部分区 dd | ~4 GB | 20+ 分钟 | 分区表都被改坏时 |

**日常只需 T1+T2**（脚本已经一次做完）。T3 只在做危险操作（改分区表、刷分区镜像）前才需要。

---

## 二、备份产物说明

运行 `scripts/backup-system.sh` 后（默认输出到 `/root/z17s-backup/<时间戳>/`）：

| 文件 | 说明 | 恢复时的用途 |
|---|---|---|
| `00-partitions.txt` | 分区表、blkid、cmdline、各分区字节大小 | **恢复前先看它**，确认分区布局没变 |
| `10-boot-sde18.img.gz` | boot 分区整段（64 MiB，含内核） | 开不了机时直接 dd 回去 |
| `20-persist-sda2.tar.gz` | persist 内容（文件级） | **Wi-Fi MAC / 蓝牙 NV 唯一来源** |
| `21-persist-sda2.img.gz` | persist 分区整段（32 MiB） | 恢复力比 tar 更强 |
| `30-config.tar.gz` | 全部 z17s 配置与 `/usr/local/{sbin,bin}` | 配置被改乱时 |
| `40-packages.txt` | 340 个已安装包 | 重建系统时批量装回来 |
| `50-rootfs-sda10.tar.gz` | 根文件系统（排除 proc/sys/dev/run/tmp/mnt） | 整机恢复 |
| `MD5SUMS.txt` | 全部产物的 md5 | **恢复前必须校验** |

### ⚠️ persist 为什么最重要

`/dev/sda2`（挂 `/mnt/persist`）只有 32 MiB，里面装着：

- `WCNSS_qcom_cfg.ini` —— Wi-Fi 配置
- `bluetooth/.bt_nv.bin` —— **蓝牙 NV（每台机器唯一）**
- `wlan_mac.bin` —— **Wi-Fi MAC 地址**（`dc:f0:90:xx:xx:xx`）
- camera / display / bms / alarm 等模块的校准数据

**这些东西一旦丢失无法再生**（是出厂校准值）。所以备份里**必须有它**，而且恢复时**最需要小心**。

（好消息：本机 persist 里 `.bt_nv.bin` 的值 `01 00 06 a5 40 1e 90 f0 dc` 与设备树硬编码一致，
所以即使丢了也有一定冗余。但 `wlan_mac.bin` 没有退路。）

## 三、把备份拉到 PC（强烈建议）

**设备坏了，设备上的备份也一起没了。** 所以备完立刻拉到 PC：

```bash
# 从 PC（Git Bash 或任意带 scp 的终端）执行
STAMP=$(ssh z17s 'ls -t /root/z17s-backup | head -1')
mkdir -p /d/z17s-backup/$STAMP
scp -r z17s:/root/z17s-backup/$STAMP/* /d/z17s-backup/$STAMP/
```

或者用仓库里的辅助脚本（如果你在 Windows 上）：

```cmd
host\windows\pull-backup.cmd
```

拉完在 PC 上再校验一遍：

```bash
cd /d/z17s-backup/$STAMP && md5sum -c MD5SUMS.txt
```

## 四、恢复：按场景选方法

### 场景 A：系统能启动，只是配置被改乱了

最简单，用仓库的部署脚本覆盖回去：

```bash
ssh z17s
cd /root/z17s-debian-ops && bash scripts/install-on-device.sh
```

或者从备份里恢复配置包：

```bash
tar xzf 30-config.tar.gz -C /
systemctl daemon-reload
udevadm control --reload-rules
```

---

### 场景 B：开不了机（boot 分区坏了）

**这是最常见、也最好修的场景。**

#### B-1 进 TWRP

关机 → 按住 **音量上 + 电源** 进 TWRP。

#### B-2 用 adb 把 boot 镜像推上去

⚠️ **TWRP 是 toybox，`dd` 不支持 `bs=1M`、`conv=fsync`，只有 gzip 也没有 `zcat`。**
命令要按 toybox 的写法：

```bash
adb shell
# 在 TWRP 的 shell 里：
mkdir -p /tmp/restore
# 先解压（toybox 的 gzip 支持 -dc）
gzip -dc /sdcard/10-boot-sde18.img.gz > /tmp/restore/boot.img

# 写入 boot 分区 —— 用 bs=4096（toybox 认）
dd if=/tmp/restore/boot.img of=/dev/block/sde18 bs=4096
```

#### B-3 验证（重要）

```bash
# 回读比对（分区 64M，只比写入的长度）
dd if=/dev/block/sde18 bs=4096 count=$((37283112 / 4096)) | md5sum
```

⚠️ **绝不能比整盘 md5** —— 镜像 19 MB、分区 64 MB，整盘 md5 必然不同。

#### B-4 或者用最简单的办法：刷现成的 boot 备份

`flash/boot_prev_before_debian.img`（64 MiB，刷 Debian 前的原始 boot）也可以直接 dd 回去。

---

### 场景 C：整机重装

#### C-1 重建分区与系统

按上游 [huanhuangyun/z17s-debian](https://github.com/huanhuangyun/z17s-debian) 的说明重刷 boot + rootfs。

**重刷前先看 `00-partitions.txt`**，确认：

- `sda10` 的大小（51.9 GiB）没变
- `sde18`（boot，64 MiB）位置没变
- 内核 cmdline 里的 `z17s.rootfs=userdata` 还在

#### C-2 恢复 persist（**最需要小心的一步**）

系统能启动后，把 persist 恢复回去：

```bash
# 方式一：文件级（推荐，风险低）
tar xzf 20-persist-sda2.tar.gz -C /mnt/persist

# 方式二：整段写入（只在文件级恢复失败时用）
# ⚠️ 先确认 /dev/sda2 没被挂载！
umount /mnt/persist
gzip -dc 21-persist-sda2.img.gz | dd of=/dev/sda2 bs=4096
mount /mnt/persist
```

恢复后验证：

```bash
ls -la /mnt/persist/
cat /mnt/persist/wlan_mac.bin        # Wi-Fi MAC 回来了
ls /mnt/persist/bluetooth/           # 蓝牙 NV 回来了
```

#### C-3 恢复根文件系统

⚠️ **不能从正在运行的系统里恢复 `/` 自己**（文件正在被使用，会写坏）。
两个办法：

**办法 1（推荐）：从 TWRP 里恢复**

```bash
# TWRP shell 里
mount /dev/block/sda10 /mnt   # 挂上根分区
cd /mnt
# 清掉旧内容（保留挂载点）
rm -rf ./* 2>/dev/null
# 解压备份（先把 tar.gz push 到 /sdcard）
tar xzf /sdcard/50-rootfs-sda10.tar.gz -C /mnt
```

**办法 2：先重启到另一个系统再恢复** —— 比较麻烦，不推荐。

#### C-4 恢复包（可选）

如果只想装回软件包而不是整盘恢复：

```bash
dpkg --set-selections < 40-packages.txt
apt-get dselect-upgrade
```

## 五、恢复后必做的检查

```bash
# 1. 系统
systemctl is-system-running       # → running
systemctl --failed                # → 0 failed
systemd-analyze time              # → userspace 约 1 分钟

# 2. USB 网络
systemctl is-active z17s-usbnet.timer                    # → active
nmcli dev show usb0 | grep -E "NM-MANAGED|REASON"        # → yes / 0
head -3 /etc/resolv.conf                                 # → nameserver 192.168.137.1

# 3. 容器
docker run --rm alpine:3.20 echo CONTAINER_OK            # → CONTAINER_OK

# 4. persist（关键）
cat /mnt/persist/wlan_mac.bin                            # MAC 地址在
```

PC 侧再验一次：

```cmd
ping 192.168.137.2
```

`ssh z17s` 能进去就说明全链路恢复了。

## 六、做危险操作前的检查清单

在**改分区表 / 刷分区 / 改内核 / 动 persist** 之前，逐条确认：

- [ ] 刚跑过一次 `backup-system.sh`，并且**已经拉到 PC**
- [ ] PC 上 `md5sum -c MD5SUMS.txt` 全部 OK
- [ ] `00-partitions.txt` 已看过，知道当前分区布局
- [ ] **串口能连上**（`host/windows/serial/_z17s_serial_passive.ps1` 能读到输出）
- [ ] 知道怎么进 TWRP（音量上 + 电源）
- [ ] `flash/` 里有可用的 boot 备份

**串口和 TWRP 是你最后的两条退路。动手前确认它们都好用。**

---

## 七、建议的备份节奏

| 时机 | 做什么 |
|---|---|
| 刚装好、验证通过 | 跑一次完整 T1+T2，拉到 PC |
| 每次改完配置/装完新服务 | 只备份 T1（20 秒的事） |
| 每月一次 | 完整 T1+T2，覆盖到 PC |
| 任何危险操作前 | 无条件完整备份 + 校验 |
